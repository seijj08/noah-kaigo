# noah-kaigo — ノアコンツェル様向け 性格・志向診断

ノアコンツェル様（札幌のデイサービス、夜勤なし）で長く働ける人と、1年後に訪問系へ進みたい人を、
面接の前に見分けるための参考情報を出すアプリです。
**この診断は合否を決めるものではなく、面接を補う参考情報です。** 出身地や学歴ではなく、本人の特性と志向を把握します。

既存の介護性格診断アプリ（myanmar-kaigo）を複製し、保存先を Supabase に変更したうえで、
ノアコンツェル様向けの7項目・回答の一貫性・診断結果レポートを追加したものです。

## 2. 使い方

### 候補者（スマホ）
1. 上の候補者用URLを Viber / WhatsApp で送る。
2. 氏名（パスポート表記）と連絡先を入力して開始。67問、15〜20分。
3. 各問に制限時間があります（通常15秒、「生活と働き方」20秒、即答8秒）。超過しても回答はできます。
4. 送信に失敗した場合は画面に「送信コード」が出ます。候補者からコードを受け取り、管理画面の「コード読込」で取り込みます。

### 管理画面
1. 担当者名を選び、管理用メールと PIN（パスワード）でログイン。
2. 「提出一覧」で候補者ごとの目安・7項目・一貫性を確認。カードを開くと詳細（診断結果レポート）。
3. 「診断結果レポートを印刷 / PDF」でブラウザの印刷画面を開き、PDF 保存できます。「回答一覧も印刷する」にチェックを入れると67問の回答も含まれます。
4. 在籍者（2期生など）が受検した場合は、詳細画面の「既存メンバーとして登録」で相性計算の基準に取り込めます。
5. 同じ氏名で複数回受検すると、一覧には最新を表示し、詳細に「受検履歴」と前回との差が出ます。

### 管理用アカウントの発行（初回のみ・Supabase ダッシュボード）
1. Authentication ▸ Users ▸ Add user ▸ Create new user
2. メールと任意のパスワードを入力（このパスワードを「PIN」として担当者に共有）。「Auto Confirm User」をON。
3. 共有アカウント1つで運用できます。担当者ごとに分けたい場合は複数作成してください。
4. Authentication ▸ Providers ▸ Email の「Allow new users to sign up」は OFF のままにします。

## 3. 採点の考え方

### 14特性・6注意点・4動機（従来と同じ）
- 各選択肢に特性ごとの加減点が付いており、合計を 0〜10 に正規化します。5 が中立です。
- 正規化は「加点は加点の満点、減点は減点の満点を分母にする」方式です（茶の花版 v1.1 / ドライバー版 v7.8 と同じ修正。旧方式では情緒安定性などが満点でも8点前後で止まるバグがありました）。
- 6つの注意点は 7 を超え、かつ該当する回答が2問以上あるときに表示します。
- 4動機は即答10問の合計を100%で配分します。

### 7項目（ノアコンツェル様向け）
| 群 | 項目 | キー | 主な質問 |
|---|---|---|---|
| A 定着プラン | 日勤で安定して働きたい | day | q53, q54, q31, q63, q64 |
| A | 仕送り額と収入の整合 | remit | q55, q56, q57, q52, q38 |
| A | 寒さと生活環境への適応 | cold | q49, q50, q51, q52, q67 |
| A | 協力して責任を持って働く | team | q58, q59, q63, q6, q8 |
| A | 同じ職場で長く働きたい | stay | q60, q61, q62, q24, q26 |
| B 訪問系ルート | 稼ぎたい意欲の強さ | earn | q53, q56, q57, q63, q64 |
| B | キャリアアップ志向 | career | q65, q66, q67, q53, q61 |

正規化は14特性と同じ方式で 0〜10。

### 目安の判定
| 目安 | 条件 |
|---|---|
| 定着プラン向き | A5項目の平均 6.5 以上、かつ 5 点未満の A 項目なし、かつ B2項目の平均 7 未満 |
| 訪問系ルート向き | B2項目の平均 7 以上、かつ「同じ職場で長く」 6 未満 |
| どちらとも言えない | 上のどちらにも当てはまらない、または回答の一貫性が「低」 |

判定の根拠（平均値や 5 点未満の項目）を画面とレポートに必ず併記します。しきい値は `judgeFit()` にあります。

### 回答の一貫性
逆の意味になる質問の組み合わせ10組（`CONSISTENCY`）を照合し、両方に該当する選択をした数で判定します。
0組=高、1〜2組=中、3組以上=低。該当した組み合わせは詳細画面に表示します。

### 面接で確かめたい点
矛盾した回答、5点未満の A 項目、5〜6点の A 項目、B 群が強い場合の志向確認、の順に最大3つを自動で挙げます。
各項目の確認方法の例文は `INTERVIEW_Q` と `CONSISTENCY[].ask` にあります。

## 4. 質問の追加・変更方法

質問はすべて `index.html` の `QUESTIONS` 配列にあります。

```js
Q("q49","10",{ja:"日本語の質問文",my:"ビルマ語",id:"インドネシア語"},[
  [{ja:"選択肢1",my:"...",id:"..."},{cold:2}],
  [{ja:"選択肢2",my:"...",id:"..."},{cold:1}],
  [{ja:"選択肢3",my:"...",id:"..."},{}],
  [{ja:"選択肢4",my:"...",id:"..."},{cold:-2}]
]),
```

- 第1引数: 質問ID（重複不可）。第2引数: セクション番号（`SECTIONS` 参照。`10` が「生活と働き方」）。
- 採点オブジェクトのキーは `TRAITS` / `RISKS` / `FIT` のキー、または動機の `money_d` `prestige_d` `freedom_d` `relation_d`。
- 加減点を変えると満点（分母）も自動で変わるため、正規化の手直しは不要です。
- 質問を追加・削除したら、`CONSISTENCY`（矛盾ペア）の質問IDと選択肢番号（0始まり）が正しいか確認してください。
- 表示順はセクション順（`SECTION_ORDER`）ではなく配列の順です。即答セクション（9）は最後に置いてください。
- 3言語の一覧と翻訳の確認状況は `docs/questions-translation.md` にあります。翻訳を直したら両方を更新してください。

## 5. データと安全

- 保存先: Supabase プロジェクト `klwmsyxxtmhxrsgstpen`（他アプリと共用）。テーブルは `noah_submissions` と `noah_members`。
- RLS: 未ログイン（候補者）は `noah_submissions` への INSERT のみ。読み取りは管理者ログイン後のみ。SQL は `sql/01_schema.sql` → `sql/02_rls.sql` の順に実行済み。
- `index.html` に書いてあるのは公開用の Publishable（anon）キーだけです。service_role / secret キーは絶対に書かないでください。
- 候補者の氏名・連絡先・回答は個人情報です。画面例や README には架空の名前だけを使い、レポートの共有先はノアコンツェル様の採用担当者に限定してください。
- 削除は論理削除（`deleted=true`）です。復旧が必要な場合は Supabase の Table Editor で `deleted` を戻してください。

## 7. 表示上の決まり

- 画面とレポートに「合否を決めるものではなく、面接を補う参考情報です」を明記する。
- 「離職を予測」「離職リスク」という言葉は使わない。
- 社名は「ノアコンツェル様」と書く。略さない。
- 「FTI」とは書かず「弊社インドネシア法人」と書く。
- 絵文字は使わない。配色は既存アプリと同じ。
